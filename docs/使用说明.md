# Kwrt 路由器 · HTTPS 解密（MITM）使用说明

> 🔧 **要改代码/排查故障？** 看速查手册：路由器上 `http://10.0.0.1:7690/doc`（源文件 `/usr/share/pktcap/CHEATSHEET.md`）

> 已在路由器上部署 **squid + 自签 CA** 实现 HTTPS 中间人解密。
> 设备装上这个 CA 证书后，就能在抓包页看到 **HTTPS 明文内容**。

---

## 1. 安装 CA 证书（在要"看内容"的设备上做一次）

**下载地址**：`http://10.0.0.1/mitm-ca.crt`

- CA 名称：`Kwrt MITM CA`
- SHA256 指纹：`00:75:06:AA:E0:9F:15:93:FF:C1:76:A2:EC:EE:12:BE:3F:D9:06:FD:5A:CB:49:E7:80:4E:11:73:BE:A1:B6:E0`

### Android（你的 OnePlus）
1. 用手机自带浏览器（**不要用微信**）打开 `http://10.0.0.1/mitm-ca.crt`，下载得到 `mitm-ca.crt`
2. 设置 → 安全 → 更多安全设置 → 加密与凭据 → **安装证书 → CA 证书**
3. 选择刚下载的 `mitm-ca.crt`，确认安装
   > Android 会提示"你的数据可能被监控"——这是正常提示。
4. ⚠️ **Android 7 以上：用户安装的证书只对浏览器生效，大多数 App 不认**（要装成系统证书必须 root）。所以：**浏览器网页能看到明文，微信/支付宝等 App 大概率还是看不到**。

### iPhone / iPad
1. 用 Safari 打开 `http://10.0.0.1/mitm-ca.crt` → 允许下载描述文件
2. 设置 → 通用 → VPN与设备管理 → 安装刚下载的描述文件
3. **关键**：设置 → 通用 → 关于本机 → **证书信任设置** → 打开对 `Kwrt MITM CA` 的完全信任

### Windows / macOS 电脑
- 双击 `mitm-ca.crt` → 安装到"受信任的根证书颁发机构"

## 2. 装完在哪看？能看到什么？

**打开 `http://10.0.0.1:7690` 就会直接落到解密内容页**（`/body`）——抓包不是常用功能，已挪到 `/packets`。

| 页面 | 地址 | 用途 |
|------|------|------|
| 👁 **解密内容（默认入口）** | `http://10.0.0.1:7690/` 或 `/body` | 看解密后的**请求 / 返回** |
| ⚙ 控制台 | `/panel` | 一键开关、抓哪些设备/网卡、解密哪些域名 |
| 📊 抓包表格 | `/packets` | 原始包列表（**默认关闭，点「开始抓包」才跑**） |

| 项目 | 能否看到 |
|------|---------|
| 访问了哪个域名、**完整 URL**（中文自动还原） | ✅ |
| 请求方法 / 状态码 / 哪个设备发的 | ✅ |
| **请求体**（POST 表单、JSON 参数） | ✅ |
| **响应体**（接口返回、网页正文、含中文） | ✅ |
| 请求头 / 响应头 | ✅ |
| 证书固定的 App（微信/支付宝/银行/抖音等） | ❌ 仍连不上，任何 MITM 都绕不过 |
| 图片/视频等二进制正文 | ⚠️ 只显示大小，不显示内容 |

**点列表里任意一行**会展开「请求 / 响应」双栏详情：

- **JSON 自动美化 + 语法着色**（键 / 字符串 / 数字 / 布尔分色）
- 中文**黄底高亮**
- 每个面板右上角有**一键复制**
- 正文若被记录上限截断，会明确标注「仅显示前 N 字符」——**转发给 App 的始终是完整内容**

详情顶部还有四个操作按钮：

| 按钮 | 作用 |
|------|------|
| ↻ **重放** | 原样把这条请求再发一次，直接看返回 |
| ✎ **编辑发送** | 把请求填进编辑器，改头/改体后再发 |
| 复制为 cURL | 一键生成可执行的 curl 命令 |
| 复制请求原文 | 方法 + URL + 头 + 体 |

**请求编辑器**（点右上角「✎ 新建请求」也可打开，可从零构造请求）：
方法 / URL / 请求头（每行 `Name: value`）/ 请求体，点发送后显示状态码、耗时、大小、响应头、响应体（JSON 美化）。

工具条支持**多角度筛选**：

| 筛选 | 说明 |
|------|------|
| 搜索框 | 空格 = 同时满足；`|` = 或；`re:` 开头 = 正则；可搜正文与中文 |
| 方法 / 状态码 | GET/POST/… 与 2xx/3xx/4xx/5xx 分组 |
| 设备 / 主机 | 下拉自动收集出现过的值 |
| 类型 | 文本 / JSON / 图片媒体 / 二进制 |
| 大小 | <1KB / >1KB / >100KB |
| 时间 | 最近 1 / 5 / 30 分钟 |
| 其它 | 只看有请求体 / 有响应体 / 含中文 |
| 「清除筛选」 | 一键恢复全部 |

> 现在是**自建的 Python 解密代理**在干活（能记录正文），已替代之前的 squid（squid 只能记 URL）。
> 旧的 `/https` 页面已废弃，会自动跳到 `/body`。
> 嵌在 LuCI 里看嫌小？页面右上角有 **「↗ 新窗口打开」**。

## 3. 开关与管理

### 🔓 解密本身也是「按需开启」的（省 CPU）

控制台（`/panel`）顶部三个按钮：

| 按钮 | 行为 |
|------|------|
| **▶ 开启解密** | 接管并解密（设备需装 CA 证书） |
| **⏸ 暂停拦截** | 立刻恢复直连，代理进程留着（随时秒开） |
| **■ 完全停止** | 清规则 + 停代理进程，**最省性能**（平时不用就选这个） |

```bash
# 命令行等价
mitm-ctl on      # 开启
mitm-ctl off     # 暂停拦截（进程留着）
mitm-ctl stop    # 完全停止（最省）
```

### ⏱ 无人监听时自动关闭（默认开启，5 分钟）

「解密内容」页**没人打开超过设定时间**，就自动完全停止解密——所有设备恢复直连，CPU 归零。
控制台里可以改时长或关掉这个功能。页面被重新打开时不会自动恢复，需要手动点「▶ 开启解密」。

### 🧹 日志保留与清理

记录文件在 `/tmp`（**内存盘**），默认 **2MB / 400 条**，超了自动裁剪。
控制台里可改上限、立即裁剪、一键清空。

### 📊 抓包是「按需启动」的（省 CPU）

抓包表格页（`/packets`）顶部有 **「▶ 开始抓包」/「■ 停止抓包」**：

- **默认关闭**——不点就不跑 `tcpdump`，路由器完全不被抓包占用
- **不看这一页的时候，默认 60 秒后自动停止**（避免忘了关一直烧 CPU）
- 需要"没人看也一直抓"时，勾选 **「无人观看也保持」**

```bash
# 命令行等价
curl -u root:root -X POST -H 'Content-Type: application/json' \
  -d '{"action":"start"}' http://10.0.0.1:7690/api/capture     # 开始
curl -u root:root http://10.0.0.1:7690/api/capture             # 看状态
```

### 🎛 网页控制台（推荐，不用 SSH）
打开 **`http://10.0.0.1:7690/panel`**，可以：

| 功能 | 说明 |
|------|------|
| **一键开启 / 关闭抓包** | 点「关闭抓包」＝立刻停止拦截，所有设备恢复正常上网 |
| **抓哪些设备** | 全部设备（整个 LAN）／只抓指定设备（填 IP，如 `10.0.0.102`） |
| **从哪些网卡抓** | 不勾＝所有来源；可只勾 `br-lan`（有线+无线客户端）或 `ztr…`（ZeroTier） |
| **解密哪些域名** | ① **全部域名**：抓得最多（证书固定的 App 首次失败后会被自动放行，见下）<br>② **仅指定域名**：只有列表里的被解密，其余原样放行<br>③ **全部解密但排除名单**：抓得全，同时把会崩的 App 域名放行 |
| **④ 自动放行名单（自愈）** | 解密失败（App 证书固定）的域名会被**自动记住并改为原样放行**，App 重试一次即恢复。可查看列表、一键清空重来 |

### 🩹 "App 打不开"是怎么自愈的

任何 MITM 都无法解密**做了证书固定（SSL Pinning）**的 App。本方案的处理方式：

1. 代理尝试解密某个域名 → 客户端拒绝我们的证书；
2. 立刻把该域名记入 `/etc/mitm/auto-bypass.txt`，**并连带放行它的主域名**（如 `img.pddpic.com` → 放行 `pddpic.com`，一次覆盖该 App 的几百个子域）；
3. 之后该域名的连接**原样透传**（不解密、用真实证书）→ App 恢复正常。

所以「全部解密」模式下**首次**可能有 App 短暂失败，几秒内自动恢复并收敛；控制台「④」里能看到已放行清单。日志里出现少量 `TLS handshake failed ... CERTIFICATE_UNKNOWN` 属**正常学习过程**，不再增长就说明已收敛。

> 从旧日志批量抢救：`logread | grep -oE "TLS handshake failed for [A-Za-z0-9._-]+" | awk '{print $NF}' | sort -u >> /etc/mitm/auto-bypass.txt` 然后 `/etc/init.d/mitm restart`。

**当前默认**：网卡 `br-lan`、模式「全部解密但排除」、排除 `pinduoduo.com` `yangkeduo.com`；自动放行名单见控制台「④」。

### 命令行（等价，SSH 到路由器）
```
mitm-ctl status              # 看状态
mitm-ctl off                 # 停止拦截（急用恢复整网）
mitm-ctl on                  # 重新开启
mitm-ctl only 10.0.0.102     # 只抓这台设备
mitm-ctl all                 # 抓整个 LAN
```
- 当前范围：`/etc/squid/mitm-targets`
- 域名白名单：`/etc/mitm/domains.txt`；模式：`/etc/mitm/mode`（`all` / `list` / `exclude`）
- 网卡过滤：`/etc/mitm/ifaces`；自动放行名单：`/etc/mitm/auto-bypass.txt`
- 服务自启：`/etc/init.d/mitm`

## 4. ⚠️ 重要影响与风险

- 现在**整个 LAN（10.0.0.0/24）的 HTTPS 都被拦截**：**没装 CA 的设备会报"连接不安全 / 证书错误"**，装上 CA 后恢复。
- **证书固定的 App 在所有设备上都会连不上**（装不装 CA 都一样）。
- QUIC（HTTP/3，UDP 443）已被**完全丢弃**以强制回退 TCP；这会略微影响速度。
- 想只影响一台设备，执行：`mitm-ctl only 10.0.0.102`（换成你要的 IP）。
- 想立刻恢复整个网络：`mitm-ctl off`。

## 5. 涉及的文件（路由器上）

| 路径 | 作用 |
|------|------|
| `/usr/share/mitm/mitm_proxy.py` | **核心：Python 解密代理（记录请求/响应正文）** |
| `/etc/squid/ssl/mitm-ca.crt` `.key` | MITM 根证书与私钥（**私钥不要外传**） |
| `/tmp/mitm-certs/` | 动态签发的叶证书缓存 |
| `/tmp/mitm-body.jsonl` | 抓到的请求/响应记录（正文页的数据源） |
| `/usr/share/pktcap/` | 网页（7690）：**默认入口 `/` → `/body`**（解密内容）、`/panel`（控制台）、`/packets`（抓包表格） |
| `/usr/libexec/mitm-nft.sh` | 应用/清除 nft 重定向规则（80→8080，443→8443） |
| `/usr/bin/mitm-ctl` | 开关脚本（`on/off/only <IP>/all/status`） |
| `/etc/squid/mitm-targets` | 解密范围（IP/CIDR 列表） |
| `/etc/init.d/mitm` | 开机自启服务（跑 Python MITM + 应用规则） |
| `/www/mitm-ca.crt` `.pem` | 供设备下载的 CA（`.crt` 为 DER 格式） |
| `/etc/squid/` | 旧的 squid 方案（已停用，保留备用） |
